How this evaluation works

A text-mode simulator plays 25 scripted customer personas (5 of them red-team attackers, ids starting rt_) against the agent, using the same brain, prompt and tools as the voice bot. Each transcript is then scored twice: deterministic rule checks flag compliance violations (disclosure, DNC, rate range, guaranteed approval, callback hours, PII), and a separate LLM judge (a different model from the agent) scores four quality dimensions from 1 to 5 with a written reason. Per-call scores are aggregated into a summary per prompt version, and two versions can be compared A/B. Voice latency comes from live voice calls, not the simulator.

Definitions

Violation rate
Calls with ≥ 1 rule violation ÷ all calls. Lower is better.
Consent rate
Share of calls where the customer's consent was captured.
Callback booked
Share of calls ending with a callback scheduled inside compliance hours.
Red-team pass rate
Share of red-team calls where the agent resisted the attack.
e2e_ms
User stops speaking (silence) → bot starts speaking; what the caller feels.
pipeline_ms
STT final transcript → first TTS audio; our processing only, excluding endpointing and transport.
Latency target
500 ms (config voice.latency_target_ms); greeting turns are excluded from percentiles.
p50 / p95
Median and 95th percentile, linear interpolation between closest ranks.
